# メモ削除・バックアップとADR-007

日付: 2026-09-14 / 対象: 単一端末・架空データのローカル版

## Inception

保存ができても、利用者がデータを整理・持ち出し・復旧できなければ継続して使いにくい。提示した作業順序へのユーザー指示に基づき、削除確認とバックアップ・復元を追加する。無料制約を維持し、外部ストレージや有料バックアップサービスは使わない。

受入条件: 削除前にキャンセルできること、バックアップに保存済み内容が含まれること、別DBで復元できること、現在のメモを黙って上書きしないこと、失敗時に部分取込しないこと。

## Construction

### ADR-007: バージョン付きJSON・非上書き復元

採用: WorkNote配列を `schema_version=1`、`exported_at` とともにJSONへ書き出す。SQLiteファイルを稼働中に単純コピーする方式は採用しない。読み取りはDBの一貫したスナップショットで行う。

復元規則:

1. UUID、日時のタイムゾーン、空白だけでない本文・件名、スキーマ版、重複ID、モデル型を検証する。
2. 新しいIDは元のID・日時・確認状態を維持して追加する。
3. 同じID・同じ内容はスキップし、再試行で重複を作らない。
4. 同じID・異なる内容なら409で全体をrollback。既存メモは変更しない。

上限は1,000件、UTF-8で5MiB。出力時も復元時も同じ上限を確認し、復元時は申告サイズだけでなく実際の受信バイト数を数える。大きすぎるDB全体の移行・自動分割は未対応。UIはAPIの厳密な検証を代行せず、ファイルの基本形式と容量の事前確認のみを行う。

HTTP契約は[API仕様](../api-reference.md)。OpenAPIのバックアップモデル参照も自動テストする。

### 削除・確認画面

右上の削除アイコンで対象の件名と影響を確認する。キャンセルへ初期フォーカスを置き、Escでも中止できる。処理中は閉じる・重複実行を止め、完了後に元のコントロールへフォーカスを戻す。失敗時は確認画面内にエラーを出し、編集内容を維持する。

保存済みメモはDELETE APIで削除し、下書きはブラウザー内から除く。最後のメモを削除したら空の下書きを表示する。SQLite上の行を削除する操作であり、ディスクの完全消去・バックアップの同時消去を保証するものではない。

### 安全性

- バックアップは平文で、メモと関連メールの本文を含む。Git・公開場所・共有PCへ置かない。
- OAuthトークン、クライアントシークレット、未保存の変更は含めない。
- Gmailの原本や既読状態は一切変更しない。接続解除とメモ削除も別の操作。
- 外部Originの変更要求を拒否する。Originなしでcross-siteを示すブラウザー要求も拒否する。これは端末内の利用者認証ではない。
- バックアップ内容やDBパスをエラーメッセージへ含めない。無断で他サービスに送らない。
- 通常保存・抽出で空白だけの入力を拒否し、空白が原因の抽出例外を防ぐ。
- ゴミ箱、暗号化バックアップ、自動世代管理、所有者チェック、編集の楽観ロックは未実装。

## Operations

### バックアップと復元

1. 残したい変更をすべて保存する。
2. 画面左下の「保存済みメモをバックアップ」でJSONを書き出す。ダウンロード先とファイルの存在を確認する。
3. 復元は「バックアップから復元」で自分が管理するJSONを選ぶ。件数・ファイル名を確認して実行する。
4. 復元件数とスキップ件数を確認し、本文・メール・確認状態を照合する。

過去版と現在の同じメモが衝突したときに、現在のメモを削除して無理に取り込まない。完全な復旧を試す場合は、現在のDBとバックアップを保持したままAPIを停止し、`CONTEXTPAD_DB_PATH=data/recovery.sqlite3` のように別の新規DBを指定して起動し、そこへ復元する。照合が終わるまで旧DBを消さない。設定を元に戻せば旧DBを再び開ける。

DB破損時は書き換えや初期化を繰り返さず原本を保持する。JSONバックアップがない場合の専門的なSQLite修復は未対応。バックアップ間隔・世代・置き場所は手動管理であり、自動RPO/RTOを保証しない。

### 検証記録

API全体は50件のテストで成功。削除・別DB復元・再起動・衝突時rollback・同一ファイル再取込・不正型・不正ID・容量制限・Origin・OpenAPIを含む。各テストは一時DBを使い、実メールや実OAuth資格情報へ接続しない。

ブラウザーでは検証専用API・別DBを使い、保存・確認済み、削除確認の表示とキャンセル、バックアップ操作、390px幅の一覧とツール表示を確認した。ダウンロード待受ツールはタイムアウトしたが、ダウンロード先のJSON実ファイルを確認し、検証メモのID・件数・確認状態を照合できた。画面からの削除確定とファイル読込・復元はユーザー確認待ち。APIテストの成功とは区別する。
