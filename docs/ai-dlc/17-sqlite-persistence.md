# SQLite保存とADR-006

日付: 2026-09-14 / 状態: ローカル実装・自動試験済み、人間による受入確認待ち

## Inception

要求: ポートフォリオに必要な作業として提示した「保存、Gmail実接続、削除・バックアップ、テスト・CI、紹介資料」を、ユーザーが「上から順にお願い」と指示した。追加サービス料金0円、架空データのみ、実施していない接続・承認を実績にしない方針を維持する。

今回の受入対象は、保存・更新・確認したメモをAPI再起動後に同一内容で読み込めること。未保存のブラウザー下書き、OAuthトークンの永続化、利用者認証、クラウドDBは含めない。

## Construction

### ADR-006: 単一端末用SQLite

- 決定: Python標準の `sqlite3` をNoteRepository内で使う。追加サーバーや有料サービスを必要としない。
- 比較: メモリは再起動で消える。JSONファイル全体の上書きは競合・書込失敗時の整合性管理が増える。PostgreSQL等は将来候補だが、単一端末の段階では導入・運用が増える。
- 範囲: 既存ADR-004のクラウドDB比較は将来案として残し、現在のローカル保存方式をこのADRで定める。
- 制約: DBは平文。所有者分離もない。個人端末で架空データを扱う試作版であり、SQLite導入だけで業務利用可能になるわけではない。

### 保存モデル

`notes`: id（主キー）、title、memo、email_json（nullable）、context_json、created_at、updated_at。

メールと抽出結果はPydanticによるJSONシリアライズと標準パーサーで扱う。日時はUTC。作成日時とIDを更新時にも維持し、本文・メールを更新すると以前の確認状態を解除する。一覧は作成日時降順、同日時はID順。検索は従来の小規模データ向け部分一致を維持する。大量件数の全件読込・検索性能は未検証。

既定保存先は `apps/api/data/contextpad.sqlite3`。`CONTEXTPAD_DB_PATH` は環境変数またはAPI側の `.env` で指定し、相対パスを `apps/api` 基準で解決する。作業フォルダーを変えても別DBにならない。起動時にDBを初期化し、モジュールのimportではDBを作らない。

### 整合性と例外

接続は操作単位で作成・クローズし、他スレッドへ共有しない。読取は同一トランザクションのスナップショット、書込は `BEGIN IMMEDIATE` 後に読取・変更・commitする。失敗時はrollback。SQLの入力値はプレースホルダーへ渡す。ロック待機上限は5秒。複数タブ間の楽観ロックや変更競合通知は未実装で、更新内容は後勝ち。

初期スキーマ版は `PRAGMA user_version=1`。未知の版、別用途のテーブル、破損を検出した場合は空DBを作って続行しない。起動時は停止、稼働中の保存障害は503/storage_unavailable。応答にDBパス、SQL、本文を含めず、メモリ保存へ切り替えて成功表示することもない。

接続・commit/rollback・ロック待機の挙動は[Python公式sqlite3資料](https://docs.python.org/3.12/library/sqlite3.html)に基づく。

## Operations

- APIテストには毎回一時DBを割り当て、利用者のDBとは分離する。
- 再オープンによる完全一致、別PythonプロセスでのAPI保存→更新→確認→再読込、16件の並行保存と確認、検索、失敗時rollback、破損・未知版の拒否、保存パス解決を試験する。
- Gmailの既存17ケースを含め、合計34件がローカルで成功。実GmailやリモートCIの成功を意味しない。
- SQLite本体・ジャーナル・データフォルダーはGit対象外。保存済みメール本文もDBに含まれるため、Gitや共有フォルダーへ置かない。
- Gmail接続解除やAPI再起動でトークンは消えるが、保存済みメモ・メール本文は残る。Google側権限の解除とメモ削除は別操作。
- 旧メモリ版からの自動移行は用意しない。起動中の旧版に保存済みデータがある場合は、停止前の退避・移行が必要。今回の切替前確認では保存件数0件だった。
- 保存工程後に削除・バックアップ・復元を追加した。[追加設計](18-note-management.md)を参照。DB破損時は原本を削除せず、保存先・権限・容量を確認する。
