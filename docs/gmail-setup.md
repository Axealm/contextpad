# Gmail接続の設定手順

更新日: 2026-09-14 / ローカル試作版向け

Gmail接続・メール検索・選択したメールの紐づけを実装しています。
Google Cloudの認証情報は未設定で、実アカウントによる接続試験はまだ行っていません。
この手順は設定を実施するための案内であり、設定完了の記録ではありません。

## 先に確認すること

- 最初は自分のテスト用Googleアカウントと架空のメールだけを使ってください。
- 保存済みメモと紐づけたメール本文は、ローカルSQLiteに残ります。API再起動でGmail接続は消えますが、保存したメモは消えません。DBは暗号化されていないため架空メールのみ使用してください。
- アプリ自体のログイン・利用者別アクセス制御は未実装です。職場の実メールを取り込んだり、ネットへ公開したりする段階ではありません。
- Gmailの読み取り専用権限を使用します。送信・削除・既読変更・添付ファイル取得は実装していません。ただし許可する権限そのものは選んだ1件だけでなくメールボックスの読み取りを許すものです。
- Googleの認証情報、認証コード、トークンはチャットへ貼り付けないでください。
- 追加料金0円の方針です。課金アカウントの紐づけ、カード登録、有料プラン、無料トライアルの開始は行いません。それらを要求されたら中止して確認します。無料枠は無制限とは扱わず、上限に達したら停止します。[Google公式の料金・上限](https://developers.google.com/workspace/gmail/api/reference/quota)

## 1. Google Cloudの準備

1. [Google Cloud Console](https://console.cloud.google.com/)にログインし、個人の検証用プロジェクトを作成します。名前の例は `ContextPad Local` です。
2. プロジェクトを選択し、[Gmail API](https://console.cloud.google.com/apis/library/gmail.googleapis.com)を開いて「有効にする」を選びます。
3. 「Google Auth Platform」の「ブランディング」で開始します。アプリ名を `ContextPad Local` とし、ユーザーサポートメールとデベロッパーの連絡先には自分が管理するメールアドレスを指定します。
4. 個人のGoogleアカウントで検証する場合、対象を「外部 / External」、公開状態を「テスト / Testing」にします。「対象 / Audience」のテストユーザーに、実際に接続する自分のアドレスを追加します。組織内専用設定を利用する場合は管理者の方針に従います。
5. 「データアクセス / Data Access」で以下のスコープを追加します。

```text
https://www.googleapis.com/auth/gmail.readonly
```

画面名は表示言語やConsoleの更新によって異なります。[Google公式の初期設定案内](https://developers.google.com/workspace/gmail/api/quickstart/python)も参照してください。ただし次のクライアント種別は、公式Pythonクイックスタートのデスクトップアプリではなく **ウェブアプリケーション** を使います。

## 2. OAuthクライアントの作成

「Google Auth Platform」から「クライアント / Clients」へ進み、「クライアントを作成」を選びます。

| 項目 | 値 |
| --- | --- |
| アプリケーションの種類 | ウェブアプリケーション |
| 名前 | ContextPad Local Web |
| 承認済みのリダイレクトURI | `http://127.0.0.1:8000/api/v1/gmail/callback` |
| 承認済みのJavaScript生成元 | 不要。トークン交換はPython側で行います |

末尾に `/` を付けず、URIを完全に一致させてください。ローカルのループバックアドレスにはHTTP利用の例外が適用されます。[Google OAuth Webサーバー仕様](https://developers.google.com/identity/protocols/oauth2/web-server)

作成後に表示されるクライアントIDとクライアントシークレットを、次のローカル設定に使用します。ダウンロードしたJSONをリポジトリへ追加しないでください。

## 3. ローカル設定

プロジェクトの `apps/api/.env` を自分の端末上のエディターで開き、2項目を入力します。この作業環境には空の設定ファイルを用意しました。別のチェックアウトでファイルがない場合は、同じフォルダーの `.env.example` を元に作成します。

```dotenv
GOOGLE_CLIENT_ID=自分のクライアントID
GOOGLE_CLIENT_SECRET=自分のクライアントシークレット
GMAIL_REDIRECT_URI=http://127.0.0.1:8000/api/v1/gmail/callback
APP_WEB_ORIGIN=http://127.0.0.1:5173
```

- `.env` はGitの除外対象です。Web側の `.env` や `VITE_` 変数にはシークレットを入れません。
- Pythonは `apps/api/.env` を読みます。既存の環境変数がある場合はそちらを優先します。
- 今回の接続は **同じホスト名のローカルHTTP** に限定しています。Webだけ `localhost`、APIだけ `127.0.0.1` のように混ぜないでください。
- 設定を変えたらAPIを再起動します。**保存済みメモはSQLiteに残ります。未保存の変更は画面の再読み込み前に保存してください。Gmailの接続状態はAPI再起動で失われるため、再接続が必要です。**

APIの起動例（`apps/api` で実行）:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Webは別のターミナルで `apps/web` へ移動して `pnpm dev --port 5173` を実行します。Webがすでに起動していれば、再起動は不要です。

## 4. 接続を試す

1. ChromeやEdgeなど通常のブラウザーで、[ContextPad](http://127.0.0.1:5173/)を開きます。Google側が埋め込みブラウザーでの認証を拒否する場合があるため、最初の接続は通常のブラウザーで行ってください。
2. 関連メール欄の「Gmail」を開きます。「設定を再確認」で未設定表示が消えることを確認します。
3. 「Gmailに接続」を選択します。ポップアップがブロックされた場合は、このローカルサイトのポップアップを許可します。
4. テストユーザーとして登録したアカウントを選び、アプリ名・要求権限を自分で確認して許可します。予期しないアプリや権限が表示されたら中止してください。組織やGoogleがアクセスをブロックした場合は制限を回避せず、設定・管理者方針を確認します。
5. 接続完了画面が出たらContextPadへ戻ります。メール一覧が読み込まれます。
6. 架空のメールを検索し、件名を選択して本文を確認します。「メールを紐づける」または「関連メールを置き換える」を選びます。
7. 雑メモを書いて「整理する」で確認し、「保存」を選びます。メールの選択だけではメモは保存されません。

未保存のメモを保持するため、接続の際に元の画面全体は移動しません。アプリと接続を別々のブラウザーで行うと、セッションCookieを共有できません。同じブラウザー内で完結させてください。

実接続の結果は[受入確認表](ai-dlc/19-gmail-live-acceptance.md)に記録します。設定ファイルが存在するだけで接続成功とは扱いません。

## 5. 解除とデータの扱い

「Gmail」内の「接続を解除」は、ローカルのトークンを消去し、Googleにも権限の失効を要求します。通信障害で失効を確認できない場合は画面に表示します。[Googleアカウントの接続管理](https://myaccount.google.com/connections)からも確認・解除できます。

API再起動・12時間経過でもローカルセッションは消えますが、それ自体はGoogle側の権限取り消しではありません。再起動後などトークンが手元にない場合はGoogle側で解除してください。既に紐づけたメール本文はメモに残り、接続解除と一緒には削除されません。

## 困ったとき

| 状態 | 確認事項 |
| --- | --- |
| 未設定のまま | `.env` の場所、IDとシークレットの両方、API再起動、環境変数による上書き |
| `redirect_uri_mismatch` | WebクライアントのリダイレクトURI、ポート、末尾スラッシュ |
| テストユーザーが許可されない | 接続するアカウントをAudienceへ登録したか、対象プロジェクトが同じか |
| `access_denied` / APIを読み取れない | Gmail APIの有効化、readonly権限の許可、Workspace管理者の制限 |
| 認証後に接続できない | 同じブラウザー・同じホスト名か、Cookieやポップアップが拒否されていないか、開始から10分以内か |
| メールが見つからない | Gmail検索条件を見直す。迷惑メール・ゴミ箱は対象外 |
| 再接続が必要 | API再起動、セッション期限、Google側の権限解除、トークン期限 |
| 本文が短い | 本文は最大20,000文字。添付・本文の取得不可時は短い抜粋に切り替え |

外部アプリのTesting状態では、今回のようなスコープのリフレッシュトークンは通常7日で失効します。[Google OAuthのトークン期限](https://developers.google.com/identity/protocols/oauth2#expiration)

## 公開前の注意

`gmail.readonly` はrestricted scopeです。公開形態やサーバーでのデータ保存・送信により、Googleの確認やセキュリティ評価が必要となる場合があります。今回のローカル実装は、それらの手続きを完了したものではありません。[Gmailスコープの公式説明](https://developers.google.com/workspace/gmail/api/auth/scopes)

利用者認証、利用者別メモ管理、暗号化した永続トークン保管、利用者別のデータ削除・保持管理、同意・プライバシーポリシー、公開審査を整えるまで実業務データや外部公開に使わないでください。AWS・Bedrockへのメール送信はこの段階では行いません。
