# 応募用ポートフォリオの公開

更新日: 2026-09-14 / 状態: 公開内容の準備済み、公開先の確定と送信は未完了

## 今回の公開範囲

応募フォームのリンク欄には、コード・README・架空データの画面・設計書を閲覧できるGitHub公開リポジトリのURLを使う。アプリ本体の外部公開、Google OAuthアプリの本番公開、AWSデプロイは行わない。ローカルの `127.0.0.1` は応募先から閲覧できるURLではない。

GitHubの公開リポジトリはFreeプランで作成できる。CIは標準のGitHubホスト型Ubuntuランナーだけを使い、課金対象の大型ランナー・有料プラン・クラウド稼働を追加しない。[GitHub料金](https://github.com/pricing) / [標準ランナーの料金条件](https://docs.github.com/en/actions/reference/runners/github-hosted-runners)

## 公開前の確認

- 現在のファイルだけでなく、公開するGit履歴の秘密情報・個人情報・実メールも確認する。
- `.env`、OAuth設定JSON、トークン、SQLite、バックアップ、ログ、実アカウントのスクリーンショットを含めない。
- READMEの画面は架空データであることを目視確認する。実接続の確認結果は本文で記録し、実メール画像を証拠として公開しない。
- AI支援の範囲、本人の確認結果、未実装・未検証の機能を区別する。GitHubのCIが未実行なら成功バッジを付けない。
- 公開するアカウントとリポジトリ名を確定し、コード・設計書・コミット履歴が第三者に閲覧可能になることを確認する。

2026-09-14時点の予備確認では、既存8コミット・142種類のGit blobに対し、秘密情報の代表的な形式、実メール形式、機密ファイル名を検査し、検出はなかった。画像3点は架空の取引先・担当者・予約ドメインの画面であることを目視確認した。パターン検査は情報漏えいがないことの完全な保証ではない。追加コミットと公開直前の対象も確認する。

## GitHubへの掲載

1. 自分のGitHubアカウントで、新しい公開リポジトリを作成する。名前は `contextpad` を候補とする。既存の履歴を送るため、README・ライセンス・gitignoreの自動生成は選ばない。
2. 作成したリポジトリのURLをローカルGitの送信先へ登録し、`main` ブランチだけを送信する。認証は本人のブラウザーや認証管理機能で行い、パスワードやトークンをチャットへ貼らない。既存リポジトリへの上書き・force pushは行わない。
3. 公開先でREADME、架空の画面、設計書へのリンクを確認する。ログインしていない閲覧者が読めることも確認する。
4. GitHub ActionsのAPI・Web・Terraform検証結果を確認する。Terraformはfmt・init・validateのみで、applyによるAWS作成は行わない。料金の有効化を要求されたら停止する。
5. 確認した公開リポジトリURLを応募フォームへ記載する。公開状態の資料を更新し、必要ならCI失敗を修正してから結果を記録する。

作成手順は[GitHub公式ガイド](https://docs.github.com/en/repositories/creating-and-managing-repositories/creating-a-new-repository)を参照。公開URLは実際の公開を確認するまで完成したリンクとして記載しない。

## 掲載後

今回は応募用URLの準備を先に行う。削除・復元の画面受入確認と、架空データを使ったデモ動画は後続に回す。実メールを保存した可能性があるローカルDBは勝手に読み出したり削除したりせず、公開物と分離して扱う。
