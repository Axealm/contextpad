# ContextPad テスト・運用設計書

文書版: 0.1 / 更新日: 2026-09-13 / 対象: ローカル試作版とクラウド版の準備

## 1. 検証方針

外部モデルの非決定性から切り離し、ローカル抽出と保存APIを自動検証する。画面は実ブラウザーで操作を確認する。Bedrock、Gmail、AWS上の動作は接続前のため検証済みに含めない。

| 検証 | 対象 | 現時点の記録 |
| --- | --- | --- |
| 抽出単体テスト | 匿名サンプルの日時・場所・期限・人物・タスク | pytestの1件で確認 |
| ヘルス・作成API | ヘルス応答、新規抽出と保存結果 | pytestの2件で確認 |
| 更新API | ID維持、作成日時維持、レビュー解除、一覧重複なし | pytestの1件で確認 |
| 異常系 | 存在しないIDの404、空メモの422、入力不正時に旧データ保持 | pytestの1件で確認 |
| フロント | 型整合性と本番用静的ファイル生成 | TypeScriptとViteで検証 |
| 画面操作 | 整理・保存・再編集・確認・検索・メール編集欄 | 手動ブラウザー確認。再現する操作は下記 |
| レスポンシブ | 1205pxの実画面、390x844の狭幅、横はみ出し・一覧開閉 | UI変更時に確認 |
| Terraform | fmt・init・validate | CI設定あり。今回の端末ではCLI未導入、ローカル未実施 |

自動テストは合計5件。テストの存在と、実クラウド環境での受入完了を混同しない。GitHub Actions自体の実行結果はリモート登録後に確認する。

## 2. テスト実行

APIディレクトリで仮想環境を有効にして実行:

```text
python -m pytest -q
```

Webディレクトリで実行:

```text
pnpm install --frozen-lockfile
pnpm build
```

buildは `tsc && vite build`。同梱ツール環境でpnpmが既存node_modulesの再構築を要求した場合は、クリーンなチェックアウトで依存関係をインストールして再確認する。今回の端末ではインストール済みのtscとviteを直接実行する検証も行う。

## 3. 画面の受入手順

1. アプリを開き、取引先Aの架空サンプルが表示されることを確認する。
2. 「整理する」でオンライン、9/17 14:00、担当Aさん、前日まで、準備タスクを確認する。
3. 保存し、件数を記録する。本文を変えて再保存しても同じメモが更新されることを確認する。
4. 確認済みにして絞り込む。再編集後は確認済みから外れることを確認する。
5. 件名と一致する語、一致しない語で検索し、一覧と該当なし表示を確認する。
6. 関連メールを折りたたみ、編集欄を開く。原文が失われていないことを確認する。
7. 狭い画面で一覧を開閉し、長い件名・長い本文が横にはみ出さないか確認する。
8. 保存前の再整理は未保存扱いになり、確認操作が無効になることを確認する。

通信切断、未保存離脱、タブ間競合、長大入力、読み上げは追加検証項目。ブラウザー操作を完全な自動E2EテストとしてCIに組み込む作業は未完了。

## 4. ローカル運用

起動手順は[README](../README.md)を参照。APIとWebの両方が必要。`/health` が成功しても画面側のJS実行が成功したとは限らないため、画面と整理操作も確認する。

| 症状 | 確認・対応 |
| --- | --- |
| 接続できない | 両プロセスの起動とURLを確認。HTMLファイルを直接開かない |
| 画面が古い | ビルド結果を配信している場合は再ビルドし、未保存変更を確認して再読み込み |
| 整理・保存に失敗 | APIの稼働、VITE_API_BASE、許可されたCORSオリジンを確認 |
| 保存したメモがない | API再起動の有無を確認。メモリ版は再起動時に復元できない |
| 抽出が不正確 | 原文を見直し、明示的な日時・場所を書いて再整理。自動予定登録はしない |

通常は各起動ターミナルでCtrl+Cにより停止する。別のアプリのプロセスを一括停止しない。現行版にはバックアップやデータ復旧コマンドはない。

## 5. Git・変更管理

- ソース、文書、テスト、依存ロック、インフラ雛形、CI設定をコミットする。
- node_modules、仮想環境、ビルド結果、ログ、秘密情報、Terraform stateや個別設定値は除外する。
- サンプル中の取引先・人物・場所は架空名、メールアドレスは予約ドメインを使う。
- ユーザーの指示、AIの変更、試験結果、人間による承認の有無をレビュー履歴に残す。
- ローカルコミットはGitHubへの公開やAWSデプロイを意味しない。作者名はリポジトリ単位で設定する。

## 7. 既知の課題

- APIに認証、ユーザー分離、永続保存、削除、競合検出がない。
- 正規表現抽出は汎用の自然言語理解ではない。日時や場所の誤検出がある。
- 空白だけのAPI入力、最大入力長、エラーの統一、冪等性を追加する必要がある。
- Bedrockアダプターは実呼び出し、リトライ、出典、厳密な余分フィールド制御を未実装。
- S3の命名はグローバル一意性の調整が必要。Terraformのruntime_modeは未使用。
- フロントの検索範囲とAPI検索範囲は完全一致ではない。
